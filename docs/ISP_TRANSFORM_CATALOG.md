# Sony a6400 ISP transform catalog

This catalog tracks transform controls, arithmetic, and transport for ARRI fine-tuning on the ILCE-6400. Addresses are tied to the image identified in each [E0505 receipt](evidence/0505-av-cam-cc-3dlut-and-ec-gamma-pipeline.md). CPU preparation order and register-write order describe software observations. The optical-to-encoded signal order and frame activation are separate verification tasks.

The host emulator in [BIONZ Look Lab](BIONZ_LOOK_LAB.md) names each row below. The badge is the one in `bionz_core::stage_catalog`. A host match does not raise it.

| EC gamma selection and knots | The directory at 0x6458443c has 36 populated records in the analyzed domain. Each record supplies nine subdivision exponents at +0x180. | EC gamma arithmetic and staging | The builder reads 96 sample positions at four-byte stride, interpolates a halfword curve at 64-code intervals, and writes 96 words. Mode 1 preserves the interpolated result. The other tested mode divides by 64 with bit-5 rounding and an increment guard at 1022. | External gamma control | The handler at 0x63beb930 stores ExGammaTableOn, PictureEffectGammaForceOFF, and ExGammaTablePointer. EC conditionally forwards state. `EC_SetExtInfo` is a separate firmware writer of a full 420-byte block into the Movie-candidate gamma buffer. A downstream +0x410 field is used as a selector on one branch, with 1–13 indexing steps of 128. Its end-to-end identity with the external message is open. | Establish transport, ownership, payload semantics and lifetime before any invocation. |
| CamCore gamma transport | PQD wrapper 0x63bf9ccc supplies four controls and two pointers. Setter 0x63cd6e44 transfers 384 bytes to window+0x15300 and writes nine words at +0x15494. Setter 0x63cd6e06 writes controls at +0x15480, +0x15484, +0x15488 and +0x154b8. Both set object+8 to 1. | Verify the metadata semantics and the hardware meaning of object+8. |
| Movie-candidate gamma buffer | EC routine 0x63dcdfa4 initializes selector bytes (0x63dcddf8), runs the EC builder with mode 0 (0x63bb9368), then copies work+0x000..0x17f (96 words) and work+0x180..0x1a3 (nine words) into the linked static buffer 0x64427840 (getter 0x63bfa890). `EC_SetExtInfo` at 0x63baf106 copies 0x1a4 bytes from an external-info record +0x278 into the same buffer. `EC::PQD_CamE` (0x63930704), whose neighbors log Movie fields (Proxy, IsSuperStableMov, [vd]), calls 0x63d4f73e -> 0x63bfa808 -> 0x63bf9ccc with buffer and buffer+0x180. Knot positions are 4, 8, 12, … 7168, 7680, 8191. | A replacement block is 96 uint32 10-bit codes, evaluated at record 31's knot positions on the 0–8191 input scale, plus the nine pair-swapped exponents. Still to establish: what drives the input scale, and the ExtInfo record format. Gamma-only ARRI test blocks (LogC3, Classic) composed on record 31 are in `artifacts/analysis/arri-gamma-test-block-2026-11-16/`. |
| Movie gamma live override | EC rebuilds buffer 0x64427840 from stock record 31 (VA 0x63e5363c, PA 0x03e5363c) on every pass. A direct buffer write is overwritten within 20 ms. A guarded mmap write of record 31 (words 0–95 = 10-bit code << 6, words 96–104 = exponents unchanged) made the buffer equal the ARRI Classic block for at least 15 s. | Grouped CamCore publication | Wrapper 0x63dd8f60 calls eight PQD setters in a fixed order: 0x63bfc5b4, 0x63bfc804, 0x63bf74a0, 0x63bf9d48 (matrix), 0x63bfc938, 0x63bf72c8, 0x63bf9f2c (3D LUT), tail 0x63bfcb60. That function passes each setter its stage parameter block from the pointer table 0x64426b20, initialized by 0x63bfa36c: +0x00 0x6446e0f0, +0x04 0x6446e19a, +0x08 matrix 0x6446e152, +0x0c 0x6446e178, +0x10 0x644eefdc, +0x14 LUT 0x64426af8, +0x18 0x6446e0e8, +0x1c control 0x64426b14. In the capture develop path at 0x638f0042, gamma publication runs before `CC: SetPreReviewDevelopParam` and the grouped wrapper. | Find the live caller of 0x63d4f636 in Movie and whether gamma and the grouped setters share a frame. |
| Per-frame CC stage refresh | In the VD sequence at 0x63934b5c (log tags `EC::VD_Pos1/2`, `LC::VD_Pos`, `TC::VD_Pos`, `VD_Post`), CC function 0x63addc7c fills all eight stage blocks from one CC output object (ctx+0x98) through accessors 0x63dd9382–0x63dd93c8. Fillers: control 0x63af9ea0, +0x00 0x63da5332, +0x04 0x63da53c2 (8 bytes), matrix 0x63af9f38, +0x0c 0x63da53ce, +0x10 0x63da541c (0x16 bytes), LUT 0x63da542a (0x12 bytes, bank pointer +0x14, request byte +0x18), +0x18 0x63da544a (8 bytes). 0x63bfa4b8 runs next in the same sequence. | Confirm the sequence runs per frame in Movie recording. If it does, a stage override must be applied after this filler on every frame, or CC will restore stock values. |
| Matrix stage gain (post-CC) | Filler 0x63af9f38 writes a 36-byte block (3 rows x 6 signed halfwords) plus halfword +0x24. With feature bit 3 of a global byte clear it copies CC output +8 unchanged. With the bit set, gain g = clamp(0xFFF00 / (4095 - L), 256, 511) in Q8 when enable byte +0x40 is set and L <= 0xffe, else 256. L is the level halfword at +0x46. Columns 0–2 become coef * g / 256. Columns 3–5 become coef * g^2 / 65536, and each row's diagonal is replaced by the negated sum of the other two, so the row sums to zero. Outputs clamp to int16. g is written back to the record at CC+0xc0, +0x46. Replay matched this model at five settings. The feature switch is bit 3 of byte 0x64351173 (global 0x64351160 through GOT slot 0x645c3288). That global is zero in the image, has 351 GOT loads and no static writer near its +0x13 readers. Dispatch item 21 (key 0x127800, callback 0x63afad20) computes the same gain from level param+0x16a and enable byte +3 of its second record, then scales bytes +6, +7, +0x0c, +0x0d of its output. Routine 0x63af6a58 copies param+0x16a from source context +0x4ae2. Live read-only observation in MSC (PA = VA - 0x60000000, verified against image code): feature byte 0x1f (bit 3 set, gain path active). The CC output object at 0x643cc384 holds a Q10 identity first half (1024 diagonal) and a zero second half. Enable CC+0x40 = 0 (g = 256), level CC+0x446 = 128, record pointer CC+0xc0 null. In user-reported Movie S-Log3 after a restart: identical values (feature 0x1f, identity CC matrix, enable 0, level 128, record null), and the matrix stage block 0x6446e152 also holds the Q10 identity. With a non-zero Movie Saturation, every one of these fields stayed byte-identical. This object and its stage blocks do not follow Movie PP and likely belong to the still or live-view develop path. | Locate the Movie chroma stage (MOV/MON bundle 0x63ade4e4 / 0x63da1162 or later). Do not use this object as a Movie target. A saturation-neutral ARRI test needs g = 256. The CC matrix itself and the two halves' signal roles still need live confirmation. |
| Movie color matrix (live, per Color Mode) — **backup-persisted table** | CC calculator 0x63ae2714 (called from coordinator 0x63da2274) fetches a base 3x3 Q10 matrix with 0x63ae4df0 from the runtime table 0x6444a044 (GOT slot 0x645c630c): modes 0–14 at +0x200 + 0x12·mode, modes 15–23 at +0x1100 + 0x12·(mode−15). It optionally applies YCbCr-domain steps, forces each row to sum to 1024, and copies the result to CC output +0x12c and +0x686 (base 0x643cc384). Live: S-Gamut3.Cine = A0 or B8 (two readings), Black & White = A4. PP Saturation does not change it. | Resolve the Color Mode → index mapping and confirm the table is refilled at boot. Verified on hardware: S-Gamut3.Cine maps to index 23 (byte 0x643cc460) and entry B8 at 0x6444b1d4. A guarded RAM-only write of the Rec.709-primary candidate was applied after a Color Mode round trip and visibly changed colors (live copies matched). The matrix is recomputed only on events (a Color Mode change confirmed), and right after boot the index is 0 (A0) until the first change. Arrivederci (`mods/arri_isp/arrivederci/`) uses this table deliberately as a reversible, backup-persisted color layer (OFF plus a normal power-off restores stock). **The table is part of Sony's persistent backup data:** a RAM change was saved into `/setting/Backup.bak` (offset 207840) on a power cycle and restored at boot. Do not override the table for RAM-only experiments; target the computed live copies or restore the table before power-off. |
| Matrix and color controls | CC computes eight-channel/four-quadrant gain and phase and nine signed halfword matrix values. The separate RGBMatrixSW calculation in capture pre-review produces Q10 coefficients and has an 18-halfword cache record. CamCore has a signed matrix writer at 0x63cd70e6 called by the wrapper at 0x63dd8f60 before its 3D-LUT call. The per-frame matrix stage block is described under Matrix stage gain. | Link the exact Movie matrix packet to its producer, determine the signal domain and locate any saturation, phase, or gain applied after it. The converter enforces row sums of 1024. |
| YCbCr and residual LUT | The 5 x 9 x 9 lattice has Y [0,64,128,192,256] and both chroma axes [-128,-96,-64,-32,0,32,64,96,128]. RefAdr supplies three signed planes. Packed output uses a verified 405-index permutation and three signed 7-bit deltas in bits [22:16], [14:8] and [6:0]. Level 1–7 scales deltas by (Level * delta) >> 3 on the observed branch. ConvSD can apply a Q14 YCbCr conversion with nonlinear tables. | Establish live ConvSD, Level and interpolation. Proportional chroma limiting, edge compression, and highlight desaturation are converter strategies to evaluate independently. |
| LUT publication and refresh | CC descriptor +0x14 carries the bank pointer and +0x18 the request. CamCore 0x63cd76a0 splits 0x654 bytes across eight windows and brackets the copies with stores of 1 and 0 at window+0x15d40. CC can rebuild on mode, level, ConvSD, six-axis and sync changes or MOV/MON transitions. | Establish the commit/fence, bank ownership and PP rollback. Trace ISO, WB, Playback exit, changes during recording and the +0x15d44 accessor separately. |
| Encoder range and chroma subsampling | The converter models 8-bit quantization and 4:2:0 for Log and Rec.709 preview. Its scale, range, clipping, sample positions and chroma filtering are model parameters. | Compare stock and modified captures, including measured code ranges and chroma siting. Chart Delta E describes model fidelity until measured against camera output. |

Keep future discoveries linked to an image identity and original instruction span. Record the input and output domains, numeric format, control dependencies, refresh behavior and verification level where known. Keep modeled ARRI targets, including the calibrated-linear alternative, traceable to their own fixtures.

## Arrivederci and ALEXA 35 follow-up

- **Movie gamma.** Live S-Log3 selected record 31, variant 1, on the 10-bit
  path. The 96 values matched the retained stock table. The nine additional
  words are the subdivision exponents in order [1,0,3,2,5,4,7,6,8]. The
  converter now models the 96 sensor positions and the stock-code bridge.
- **Base matrix.** The CC calculator at 0x63ae2714 selects a table entry and
  normalizes rows to 1024. Movie S-Gamut3.Cine selected A0 on some boots and
  B8 after a Color Mode round trip. A live test wrote the two computed
  copies at CC+0x12c and +0x686 without a PP change and saw no visual
  change. Trace the publication after recomputation to locate the point
  where a conditional runtime replacement can take effect.
- **Backup persistence.** The B8 table source used by the reviewed
  Arrivederci build was persisted to Sony's backup. The existing
  [mod warning](../mods/arri_isp/arrivederci/README.md) applies to that build.
- **CC fine-tuning.** The stage matrix filler at 0x63af9f38 has a feature
  gate and an optional level-dependent Q8 gain applied differently to its
  two halves. The sampled Movie S-Log3 state held a unity CC stage and an
  idle LUT request. Film chart comparisons should isolate hue/phase,
  chroma compression, and high-luma desaturation as separate experiments
  after the Movie publication and activation paths are verified.
- **ALEXA 35 target.** The converter adds AWG4/LogC4 and a separate ARRI
  Gamma 2.4 Rec.709 LUT target. AWG4 primaries and LogC4 are specified
  transforms. Sony sensor-to-ALEXA 35 rendering, including the effects of
  debayer, sensor response and texture, remains a paired capture task.

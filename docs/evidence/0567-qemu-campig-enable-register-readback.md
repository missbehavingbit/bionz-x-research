# E0567 — Opt-in CamPig interrupt-enable readback

Date: 2026-11-17. Offline follow-up to [E0566](0566-qemu-ee-callback-stays-pending.md).

## Model

`CAMPIG_ENABLE_READBACK=1` sets the machine option `campig-enable-readback=on`. It maps the existing plain register-file device over one 32-bit word at `0xF3000050`. The word resets to zero and retains the value written. The default policy leaves this address on the existing unimplemented device. This scope comes from original firmware read-modify-write instructions at `0x63CC3292/98` and `0x63CC329C/32A2` and the [pinned a5000 CamPig implementation](https://github.com/Oein/a5000-emulator/blob/6ad36bd7b0411d55a5920447ff51e3de01f8cb9b/qemu-overlay/hw/misc/cxd90014_campig.c). The observations qualify bits 26 and 27. Other bits are retained by the experimental word without a claim about their hardware semantics.

The original a6400 ISR at `0x63CC3850` reads and acknowledges status at `0xF3000048/4C`. The handler forwards `+0x48` with instance tag `0x20000000` to `0x6375AB70`. That dispatcher matches each firmware table record against all bits in the tagged mask, copies descriptors in table order, then calls `0x63CC31D6` on the copies. The enable word alone establishes no frame source, callback order in a real frame or statistics payload. No status, IRQ completion or result data was added.

## Verification

- Reused the existing QEMU build inputs. `build.py` takes the compiler and expanded linker arguments from `ninja -t compdb -x`, replaces the board object and links into a separate WSL scratch directory. The original binary SHA-256 remained `2720703c2b200a1dbaf9ee7c7e4a99e3e6a8c026b21e7517bcd7b836354486a7`. The experiment binary SHA-256 was `87c324f41fdc42dc88d479bf87eb63a0feaf839b8b07fd523439ec2056d26264`.
- The paused QEMU test `qtest.py` checked both policies against the new binary. Off reads zero before and after writes. On reads zero initially, then reads back `0x08000000` and `0x0C000000` after their respective writes, then returns to zero on system reset. Adjacent `0xF3000054` still reads zero after a write with either policy. The launcher passed `bash -n`.
- Paired real-firmware replays used the new binary, E0561 legacy inputs (ORIL SHA-256 `90d515cfec8b936f1ba9a69dcac462816b880297752a652474d67c4bba39125e`), `EVSEL_LATE_US=500` and `icount shift=0,sleep=on`. From the repository root in WSL, set `A6400_QEMU_DIR` from `qemu-dir.txt`, then run `python3 -u` on `retry-off/replay.py` with `CAMPIG_ENABLE_READBACK=0` and on `retry-on/replay.py` with `CAMPIG_ENABLE_READBACK=1`. Each script builds the retained passive trace plugin and starts `qemu-a6400/run.sh` with a fresh overlay. Both exited 0 via QMP quit after the 70 s snapshot.
- In both replays the original firmware wrote `0x08000000` at PC `0x63CC32A2`. At the second read (`0x63CC3292`), off returned zero and on returned `0x08000000`. The subsequent firmware store (`0x63CC3298`) wrote `0x04000000` off and `0x0C000000` on. In both replays the step-32 request/report remained `0x032E/0x0326`, and the callback promotion, completion load and Ydet producer each had zero hits. These observations qualify the readback fix and leave the frame event boundary open.
- The first separate-session test attempts could not open the executable under the earlier Linux scratch directory. The repeated build and tests ran in a single WSL session. Their receipts, command arguments and test scripts are under `artifacts/qemu-a6400/campig-enable-readback/`.
- The first Windows suite executed 1,225 tests and reported 7 failures, 146 errors and 39 skips. The seven failures were generated status synchronization checks. After synchronizing the status snapshot and SVG with E0567, the 39 focused status tests passed, and the full Windows rerun reported 146 errors and 39 skips, including Windows native-module load errors. The focused QEMU checks are separate from that result.

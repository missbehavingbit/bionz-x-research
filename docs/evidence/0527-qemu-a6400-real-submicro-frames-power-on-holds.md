# E0527 — Real a6400 sub-micro frames captured (one read-only 4 KiB `/dev/mem` page) and replayed; with the timing-event block the link runs all three slots and the power-off (factor 7) is gone

Date: 2026-11-16. **One authorized read-only camera observation** (standing authorization: a
single bounded 4 KiB `/dev/mem` page, no sweep, no write outside `/tmp_bt`, owned helper removed,
camera responsiveness verified). Everything else is offline. `emmc.img` is unchanged.

Labels: [C] confirmed by a run receipt or disassembly, [I] inference, [A] assumption.

## 0. Short answer

1. **Capture [C].** On the live ILCE-6400 (debugger `PONG`, pid 703; uptime 6046 s before):
   `dd if=/dev/mem of=/tmp_bt/e0526_page_03443000.bin bs=4096 skip=13379 count=1` (`dd_rc=0`, 4096 B),
   followed by `camera_debugger read` and `rm`. The camera's `/proc/cmdline` has the same memory map as
   the emulator's main cmdline (`memrsv=0x1A5E000@0x02E68000`, `wbimem=0x500000@0x03085000`), so the
   page lies in reserved memory.
   - The first attempt's host-side `read` failed: Git Bash rewrote the camera path. The chained `rm`
     then removed the helper, so the identical read was repeated once.
   - Two single-page reads in total. `/tmp_bt` returned to baseline after each. Uptime advanced
     monotonically (6046 → 6094 s), and the debugger still answered `PONG` afterwards.
2. **Content [C].** The page has six CRC-16/CCITT-FALSE-valid 128-byte frames at the addresses the
   emulator predicted (E0526):
   - RX (micro → CPU), contiguous: **slot A `0x034433A4`** (type 0x20, task-48 packet; byte 28 = 0x01
     = power lever ON), **slot C `0x03443424`** (type 0x60, new on the a6400), **slot B `0x034434A4`**
     (type 0x30 TLV frame).
   - TX (CPU → micro): `0x034435C8` (0x21), `0x03443648` (0x61), `0x034436C8` (0x31).
   - Slot B TLVs: 00 `01 02 01 38` (micro version), 01/02/10 zero, 03 `00 00 00 03` (bit 6 clear,
     i.e. not a power-off frame, unlike the a5000 snapshot), 0a (32 B), 0b (16 B), and 14 (12 B, not
     present on the a5000).
3. **Replay [C].** The board answers SIO ch3 with the captured 384-byte RX buffer
   (machine property `submicro-frames`, cut by `run.sh` from the hash-checked page): 0x31 → slot B,
   0x61 → slot C, any other 128-byte frame → slot A. That is the a5000 `a5k_submicro_xfer` rule,
   extended for slot C. Frames are replayed as captured, so the slot-A clock bytes stay at the
   capture time [limitation].
4. **Slot A needs the engine tick [C].** With slot B replay alone (`0x31` only, 3,374 exchanges),
   factor 7 remained, because slot A was never clocked. Ported `cxd90014_evsel.c` from
   `Oein/a5000-emulator` (GPL-2.0, attributed): the camera timing-event block at `0xF3C30000`,
   with frame events on IRQ 83 and 1 MHz one-shot comparators on IRQ 84. a5000 `RE_ENGINE_TICK.md`
   §1–2: the engine's 1/8-frame int_HS comparator chain sets the slot-A permit flag. The a6400
   av-cam programs the same page (E0525 map) and registers liro-83/84. Result:
   `liro-83` 1,557, `liro-84` 18,573, and **2,171 slot-A (`0x21`) plus 2,171 slot-C (`0x61`)
   exchanges** next to 3,186 slot-B ones.
5. **Power stays on [C].** Once all three slots are replayed (`console-replay-run.log`), no
   `add_off_factor` appears in about 26 s of guest time. Before, `add_off_factor: 0x7` arrived at
   2.05 s in every run.
6. **New boundary [C].** `snsc_boot_time` stops at 1.725 s with `B` and no `E` for
   **`Og 001_ObjMic`** (microphone object start) and `Mi 0DC_libObj.so`. Earlier runs had the same
   unfinished ObjMic start, hidden by the power-off. No unusual `wchan`: the wait is an ordinary
   message or futex wait. `THREAD_INFRA0` still waits in `sugilite_ioctl` (GPU), and av-cam task 43
   in `twai_flg` (vsync flag).
7. **Speed [C].** The ported GPIO pin-IRQ pulse is now 50 µs instead of the a5000's 1 ms. At level
   trigger the ISR re-entered for the whole pulse. `liro-129` drops from 2,058,785 to 49,917 per run.
   This is a deviation: the real GPIO interrupt latch/ack is not modelled.

## 2. Assumptions and limits

- Engine frame period 33,367 µs is the a5000 constant [A for the a6400].
- Replayed micro frames are static. Battery, clock and media fields never change, and slot-A keys
  stay at the capture state (lever ON, others as captured).
- The capture is one moment of a running camera. Fields that the real micro updates per exchange
  are frozen.

# E0669 - a6400A offline Senser dispatch, native read gates and own-image L3 prefix

Date: 2026-11-15. **Entirely offline.** The camera was not enumerated, opened,
switched, uploaded to or written. No installer, preload hook, updater session,
SD access or physical-memory scan was used. No partition capture is claimed.

Follow-up: [E0670](0670-a6400a-ghidra-reader-consumers-and-fixed-partition-candidate.md)
uses the now-working Ghidra backend, traces the actual read consumers, and
qualifies additional original-byte fixtures without camera access.

## 1. Result

The preserved 1.01 package explains the
[E0668 live refusal](0668-a6400a-live-senser-entry-and-recovery.md):
**there is no registered FileControl factory to unlock in the examined stock
Senser tables.** Missing functions fall through the generic `NoAction(0x80)`
path. MemoryDump is absent as well. This is stronger than inferring a disabled
file handler from a USB status, but it does not attest live installed bytes or
rule out every alternative IPC/plugin path.

The response's **version 3 is generated by the reply builder**, not evidence
that changing the request version would activate FileControl.

Other adjustment commands really are level-gated. Selected `RAM_READ` commands
pass the original admission decision, but downstream routing, memory ownership,
side effects and flash applicability remain unqualified. They are **not ready
for a live read**, let alone a physical memory sweep.

Five stock native external-command registrations are reconstructed before IPC:
features **1, 2, 4, 6, 7**, each declaring **8,192-byte receive/send buffers**.
These are not a live kernel registry. In particular, feature 7's request path
can delete configuration files and write backup state before its command
dispatcher reaches a "Get" operation.

Separately, the own a6400A `im.elf` and interpreter execute **1,183 original
instructions** under the default L3 stop policy, reaching `brk(0)` with **zero
syscall replies**. This is a new bounded loader prefix, not a booted camera.

## 3. FileControl is a missing registration, not a hidden file-read flag

All addresses below are linked ELF coordinates, not camera runtime addresses.
Thumb function entries carry bit 0; instruction addresses do not.

| Selected stock table | Linked address | Function IDs before its sentinel |
| --- | --- | --- |
| `pFunc_level_A` | `0x5ADDC` | `10, 20, 30, 40, FF00, FF02` |
| `pFunc_level_B` | `0x5AE14` | `40, 10, 20` |
| `pFunc_level_C` | `0x5AE34` | `40` |

Factory pointers are resolved from original ELF relocations; no missing entry
is invented. Original authentication completion at `0xFCC0` selects **C/B/A
for levels 1/2/3**, respectively. Its terminal-disable flag is 1/1/0.

Original `ParseCheck` at `0x12418` tests table membership. Original `Parse`
at `0x127A0` walks the same table, calls a matching factory, and falls back
when no match or no command object is returned. At `0x127DE` it prepares
literal status **`0x80`** for the `NoAction` constructor. There is no separate
FF01 branch with a file-specific flag in this decision.

**128 original membership controls** cover null/A/B/C table fixtures,
`10/20/30/40/FF00/FF01/FF02/FF03`, request versions 0/3 and both terminal flag
values. FF01/FF03 remain missing in every case. Six additional `Parse` windows
reach the original `NoAction` constructor boundary with status `0x80`.
Allocation and discarded-input construction are explicit ABI fixtures; no
discarded data or USB worker is claimed.

Original `NoAction::DoExecute` at `0x10D34` copies its status to header byte 11.
The original reply prefix at `0xEFA4` writes **3** to header byte 8 and zeroes
the payload size for a null response. Separate bounded windows reproduce:

```text
00000000 01ff 0100 03 00 00 80
size=0   FF01 seq=1 version=3 status=80
```

FF03 and a second sequence value are also checked. This is a reproduction of
the decision/header shape, **not a complete serviced USB transaction**.

## 4. Other Senser paths and real gates

| Path | Original-byte finding | Remaining boundary |
| --- | --- | --- |
| `0x10` ProductInfo | Selects `libpro%02X.so` by the command's high byte. `00F1` with terminal disabled prepares `NoAction(1)`; otherwise it reaches plugin lookup. | Plugin lookup is not a root file API. |
| `libpro00 command00F1`, `0x714` | Returns 1 without reading the enable payload or writing state. | A positive return is not terminal activation. |
| `0x40` AdjustControl | Uses a 1,547-record, 72-byte command table at `0x19214` and per-entry access bits. | A registered name is not proof of read-only effects. |
| `0xFF00` TestMode | Constructs `HostCommunicationCommand`; its execution path opens `/var/fifo/sen_host_req` and `/var/fifo/sen_host_res`. | Application-side FIFO consumer and its state are not supplied. |
| `0xFF03` MemoryDump | No entry in any of the three tables. | No direct memory-dump command is qualified. |

The adjustment record for `(block 0601, command 1F)` is `TERM_MODE`, index 759,
stored code **`0x801F`**. At `0x1352A` the original instructions mask `0xE000`;
an exact `0x8000` class branches to rejection before level-specific admission.
The tested enable payload is refused at **all three levels**, producing
transaction type `0xFF`. Changing only authentication or terminal state does
not add FF01/FF03 to the tables.

The controls deliberately distinguish this from working access-level gates:

| Adjustment candidate | Stored code | Original gate result |
| --- | --- | --- |
| `0601/FE RAM_READ` | `00FE` | Admitted, type 0, levels 1/2/3 |
| `0304/FE RAM_READ` | `40FE` | Rejected at level 1; admitted at levels 2/3 |
| `0603/01` backup `READ` | `0001` | Stops earlier at `tlog_file_exist`; filesystem/trace state is unknown |

These are stops **before routing**, not returned memory or backup data.
The broader bounded name scan retains RAM, NOR, MPR and Jiritsu candidates.
Their names do not establish host-CPU memory, a raw `nflasha` namespace or safe
transfer/lifecycle behavior. No candidate is promoted to a physical reader.

## 5. Native `/dev/usb/usb_extcmd` declarations

Senser pFunc IDs and Mass Storage `extcmd` feature IDs are different namespaces.
The latter are dynamically registered by services, not a fixed raw-flash
command table in the kernel.

Original `InitCmd` windows allocate an explicitly constructed 84-byte message
and stop before registration IPC. They prepare message `0x20000001` with these
feature IDs and 8,192-byte receive/send capacities:

| Feature | Owner | Callback's command family / caution |
| --- | --- | --- |
| `1` | DevInfoSender | Model info and supported feature list; not a file reader |
| `2` | KikiLogSender | Log initialization/readout from `kikilog_get_compress`'s buffer; not an arbitrary pathname |
| `4` | ExtBackupCommunicator | Backup lifecycle, power-off and host/network registration operations; not raw flash readback |
| `6` | LensCommunicator | Supported commands and mounted-lens information |
| `7` | NetworkServiceInfo | Streaming/Wi-Fi getters and setters; unsafe to classify all getters as read-only |

For feature 7, `ReqTransferCmp` calls `checkAndRemoveAllConf` at `0x6BCA`
before the command switch. Original instructions at `0x4178` read backup state;
one state branches through **`unlink` calls and `Backup_write`**. No actual
configuration or credential values were acquired. This path was not exercised
on the camera.

The existing original ARM `msc_extcmd_trace --debugger-abi` replay also passes:
opcode `0x7A`, feature `0x23`, four ioctl branches and declared registration
fields are corroborated. Its list/allocation/locking fixtures are not a live
registration. Feature `0x23` still needs the custom daemon; no stock service
discovered in this scan supplies it. The separate updater protocol is not
reclassified as a safe reader or invoked. The 285-entry `av-cam` command table
from E0506 is **not** this USB registry.

## 6. Own-image L3 baseline and L2/L3 selection caution

The offline L3 prefix selects only these 1.01 inputs:

| Input | Bytes | SHA-256 |
| --- | --- | --- |
| Packaged `nflasha7` ext2 image | 5,103,616 | `45052699b0f6a765a2652185a64818327195f60f3d60078bfcd6f8b8564698ee` |
| Main `im.elf` | 23,240 | `de26c4b208d9d4524a0d0e76474b626ddd5902a868c2b271d19ec1c7caffdbe5` |
| Root `ld-2.11.2.so` | 101,736 | `c37bf426bf64d644f0d0a428ab6e4366d31b232c96985de7bb20399a7fc5fecc` |

The fast symlink `/lib/ld-linux.so.3 -> ld-2.11.2.so` is checked in raw ext2
metadata, not guessed from a host filename. The application declares that
interpreter. `InterpreterProbe` uses `ilce_6400a`, a declared initial stack,
the default **stop-on-syscall** policy, 100,000 instructions maximum and a
2-second execution budget.

Result: **1,183 instructions**, Thumb `svc #0` at **`0x40010B14`**
(post-SVC PC `0x40010B16`), `r7=45`, `r0=0`: **`brk(0)`**.
Zero syscall results, filesystem services or UIPC replies are supplied.
The exact harness, policy, source identities and result are retained in
`l3-prefix-01/report.json`.

The current `run_nflasha1_boot --target` still gets its boot set from the
historical `NflashaBootSet.from_evidence`; `probe_interpreter --target` still
loads historical inventory paths. Changing the profile alone does **not**
select the a6400A images. Those wrappers were not run as supposed 1.01 boots.
The original-a6400 E0510 shell result is not transferred to this body.
Next L2/L3 work must wire explicit own-image sources and preserve the
main/updater distinction and per-image address guards.
